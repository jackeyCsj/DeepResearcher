## 澄清 token 预算口径（答疑）

用户问：ContextConfig.max_tokens=30000 是单次调用上限还是一次调研总预算？

结论：**单次 LLM 调用的上下文软上限**（`context_builder.build_context()` 用它算
`history_budget = max_tokens*(1-reserve_ratio) - system_tokens`），不是任务级配额。

项目现状与发现的缺口：
- 任务级只有观测没有预算：`llm_client._track_usage()` 累加 `total_prompt_tokens /
  total_completion_tokens`，由 `api/app.py:348` 的 `total_tokens` 字段暴露，但无硬上限、无熔断。
- **缺口 1**：`history_compactor.summarize_all()` 把 history 拼成最多 100000 字符一次性喂给 LLM，
  这次压缩调用的输入不受 30000 约束，可能远超预算。
- **缺口 2**：`compress_old_rounds()` 把所有待压缩 tool 结果拼成一个 batch 请求，同样无预算检查。
- 已有节流手段：工具结果字符截断（researcher.py: MAX_TOOL_RESULT_CHARS=20000、
  MAX_DENOISE_RESULT_CHARS=10000）、40% 预算阈值触发压缩、超预算 summarize_all 兜底。

后续若要补：加 task-level budget cap（基于 tag 归因的累计拦截）+ 压缩调用自身的输入分片上限。
